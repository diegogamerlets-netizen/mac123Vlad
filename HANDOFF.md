# Облик: пакет для передачи разработчику

Сайт заказа индивидуальных скульптур по фотографии: лендинг, форма заказа с созданием макета через нейросеть (4 ракурса), оплата ЮKassa, проверка адреса (DaData), расчёт доставки (СДЭК), оферта и политика конфиденциальности, админка заказов. Продавец: ИП Шадура К. И.

Этот файл описывает, что внутри, как запустить и что ещё не доделано. Секретов в пакете нет: ключи нужно создать заново (см. раздел «Секреты»).

## Стек
- **Python 3.9+, только стандартная библиотека** (внешних зависимостей нет, `requirements.txt` не нужен).
- Бэкенд: один процесс `server.py` (`ThreadingHTTPServer`), хранилище: файлы в `data/` (`orders.json`, `gen/<id>/…`).
- Фронтенд: статические HTML (`templates/`), CSS и JS без сборки (`static/`).
- Внешние сервисы: OpenAI (картинки и проверка), ЮKassa, DaData, СДЭК.

## Запуск локально
```
copy .env.example .env      (заполнить; без ключей работает демо-режим)
py server.py                (http://localhost:8000)
```
Без ключей: макет = исходное фото, адрес не проверяется, доставка 500 ₽ фиксированно, оплата = страница-заглушка.

## Основной поток
1. `/create`: выбор продукта («Скульптура» 1–6 человек или «Этапы взросления» 3 фигурки), загрузка фото (+ необязательно фото слева/справа/сзади), стиль.
2. `POST /api/generate` запускает **фоновую задачу**, клиент опрашивает `GET /api/generate/<job>` (шаги и прогресс). Генерация: вид спереди (high), затем боковые и задний параллельно; после каждого вида модель зрения проверяет «нет ли тёмных пятен», при них перегенерация (до 3/2 попыток, бюджет `AI_QA_BUDGET_SEC`).
3. Состав и стиль фиксируются на сервере в `data/gen/<id>/meta.json`: **цена считается на сервере**, клиент её не задаёт.
4. `POST /api/delivery/quote` (адрес перепроверяется на сервере), `POST /api/orders` (две отдельные галочки согласия: оферта и персональные данные; сохраняется время, IP и версия документов), затем редирект на оплату ЮKassa (или демо-страница).
5. Статус заказа: `/order/<id>`, проверяется и по вебхуку `/api/yookassa/webhook`, и опросом API при открытии страницы.

## Развёртывание
Целевая схема: VPS Selectel (Ubuntu 24.04) → nginx (HTTPS) → `server.py` на `127.0.0.1:8000`. Скрипты и подробности: `DEPLOY.md`, `deploy/`.
**Статус:** сервер в Selectel создан (Москва, `ru-2a`, 1 vCPU / 2 ГБ, IP 135.106.173.99), но **вход по SSH из среды разработки не удался** (приветствие SSH не приходит), поэтому сайт на сервер ещё не загружен и HTTPS не настроен. Домен куплен в Selectel; A-записи на IP нужно проверить.

## Секреты
`.env` в пакет **не входит**. Шаблоны: `.env.example`, `deploy/.env.production.example`. Нужно создать и вписать самостоятельно: `OPENAI_API_KEY`, `YOOKASSA_*`, `DADATA_TOKEN`, `CDEK_*`, `ADMIN_PASSWORD`.
Ключи OpenAI и BytePlus, которые использовались при разработке, передавались через чат: их нужно **отозвать и создать заново**.

## Что осталось сделать
1. Загрузить сайт на сервер и поднять HTTPS (`DEPLOY.md`), проверить вебхук ЮKassa `https://<домен>/api/yookassa/webhook`.
2. Юридические страницы (`templates/offer.html`, `privacy.html`, `legal.html`): заполнить выделенные поля (адрес ИП, email, срок хранения фото, регион серверов). Плашка «Черновик» исчезнет сама.
3. Роскомнадзор: уведомление об обработке персональных данных, при передаче фото в OpenAI (США) отдельно о трансграничной передаче; проверка текстов юристом.
4. Прогнать ЮKassa (тестовый магазин), СДЭК (тестовая среда), DaData с реальными ключами; проверить чек 54-ФЗ (`YOOKASSA_VAT_CODE`, `YOOKASSA_TAX_SYSTEM`, `YOOKASSA_RECEIPT`).
5. Картинки в блоках «Идеи» и «Примеры стилей» собраны из присланных заказчиком изображений; проверить права и при необходимости заменить.
6. Автотестов в проекте нет, проверки делались вручную и скриптами; стоит добавить тесты на расчёт цены и валидацию заказа.

## Известные особенности
- Результат нейросети недетерминирован: сходство и цвет могут отличаться от попытки к попытке; есть автопроверка цвета и кнопка «Создать заново».
- Генерация занимает 2–5 минут и стоит четыре картинки (плюс повторы): следите за балансом OpenAI, лимит `GEN_LIMIT_PER_HOUR` защищает от злоупотреблений. Лимит хранится в памяти процесса (сбрасывается при перезапуске).
- Задачи генерации хранятся в памяти: при перезапуске сервера текущие макеты теряются (клиент получит понятную ошибку).
- Заказы хранятся в `orders.json` (блокировка внутри процесса): для роста нужна БД.
